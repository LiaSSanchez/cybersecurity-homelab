# Apache Log Analysis

## Objective

Review Apache access logs to identify web requests made to the target server and understand what information is recorded during normal activity and scanning.

## Lab Environment

- Analyst machine: `CyberLab-Ubuntu`
- Target machine: `CyberLab-Target`
- Analyst IP: `10.10.10.10`
- Target IP: `10.10.10.20`
- Web service: Apache2

## Commands Used

```bash
sudo tail -n 20 /var/log/apache2/access.log
```

```bash
sudo tail -f /var/log/apache2/access.log
```

## Results

The Apache access log showed requests coming from the analyst machine at `10.10.10.10`.

The log entries included information such as:

- Source IP address
- HTTP request method
- Requested path
- HTTP status code
- User agent

Normal `curl` requests appeared in the logs with successful `200` responses.

The logs also showed requests generated by Nmap during service detection, including requests for unusual paths and entries using the Nmap Scripting Engine user agent.

Using `tail -f` allowed me to monitor the log in real time and see new HTTP requests appear immediately after sending them from the analyst machine.

## What I Learned

This exercise demonstrated how web server logs can be used to identify activity against a system.

Logs provide useful information about who connected to a service, what they requested, and whether the request succeeded or failed.

I also learned that reconnaissance tools such as Nmap can leave recognizable traces in server logs, which can help defenders identify scanning and enumeration activity.
